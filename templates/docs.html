Обзор

pallet-dimensioner — веб-сервис на FastAPI, который по кадрам с двух ортогональных веб-камер (top — сверху вниз, side — горизонтально) считает габариты паллеты (длина, ширина, высота), опрашивает подключённые весы (scale_api) и показывает всё это на рабочем месте оператора вместе с QR-кодом для наклейки на паллету.

Точка измерения (post) — это одна физическая станция: две веб-камеры + опционально весы. Точек может быть несколько (каждая — своя пара USB-камер на этом же хосте), но live-видео и измерение работают только пока физически подключено соответствующее железо.

Быстрый старт

# Поднять сервис через Docker Compose
cp .env.example .env
docker compose up -d

# Проверить health
curl http://localhost:8012/health

# Открыть список точек в браузере
http://localhost:8012/posts

Точки измерения

Точка создаётся одним вызовом — камеры привязываются по индексу устройства (/dev/video0 → 0), весы — по URL уже поднятого scale_api:

curl -X POST http://localhost:8012/api/posts \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Пост 04",
    "camera_top_device_id": 0,
    "camera_side_device_id": 1,
    "scale_api_url": "http://192.168.12.147:8011",
    "wms_endpoint": "http://wms-backend.local:8000/api/v1/pallet-measurements"
  }'

Дальше — POST /api/posts/{id}/start запускает камеры и пайплайн измерения. ROI, HSV-пороги фона и координаты ArUco-маркеров создаются с разумными дефолтами (см. Настройки) — их нужно донастроить под конкретный пост через PATCH перед реальной эксплуатацией.

API Endpoints

POST/api/posts

Создать точку. Тело — см. пример выше. Возвращает созданный объект точки с id.

GET/api/posts

Список всех точек.

GET/api/posts/{id}

Конфигурация одной точки.

PATCH/api/posts/{id}

Частичное обновление — ROI/HSV/ArUco камер, весы, WMS-эндпоинт, пороги стабилизации. Точку нужно перезапустить (/stop → /start), чтобы воркер подхватил новый конфиг.

DELETE/api/posts/{id}

Остановить воркер (если запущен) и удалить точку.

POST/api/posts/{id}/start

Открыть обе камеры и запустить фоновый цикл измерения для точки.

POST/api/posts/{id}/stop

Остановить цикл измерения и освободить камеры.

GET/api/posts/{id}/state

Текущее состояние: status (running / camera_offline / calibration_lost / stopped), length_mm/width_mm/ height_mm, cross_check_passed, stable, weight.

GET/posts/{id}/stream/top, /posts/{id}/stream/side

MJPEG-видеопоток с камеры точки (multipart/x-mixed-replace) — вставляется напрямую в <img src="...">.

GET/posts/{id}/qr.png

QR-код (PNG) с текущими габаритами и весом — см. формат ниже.

Рабочее место оператора

GET /posts/{id}/workplace — страница с двумя живыми видео (top/side), текущими длиной/шириной/высотой, показанием весов и QR-кодом. Цифры и QR обновляются поллингом /api/posts/{id}/state каждые ~700 мс — отдельный WebSocket не нужен для этого объёма данных.

Формат QR-кода

QR кодирует компактный JSON:

{
  "post_id": "post-04",
  "post_name": "Пост 04",
  "length_mm": 1195,
  "width_mm": 800,
  "height_mm": 1487,
  "cross_check_passed": true,
  "weight": 820.5,
  "weight_unit": "kg",
  "timestamp": "2026-08-18T10:23:41+00:00"
}

Поля, для которых ещё нет данных (точка не запущена / маркеры не найдены), в QR не попадают.

Калибровка объектива (файлы camera_intrinsics_top.json / _side.json в data/posts/{id}/) не обязательна для запуска — без неё просто не корректируется дисторсия объектива. Для точных измерений прогоните scripts/calibrate_post.py так же, как в headless-режиме (см. README).
