# pallet-dimensioner

> Веб-сервис измерения габаритов паллет (длина, ширина, высота) двумя ортогональными веб-камерами
> + весы. Точки измерения (посты) создаются через API, рабочее место оператора показывает живое
> видео с обеих камер, стабилизированные габариты, вес и QR-код с итоговыми данными.

Один физический пост = две веб-камеры (top сверху вниз, side горизонтально) + опционально весы
(интеграция с [[scale_api]]) на одном хосте (Raspberry Pi / mini-PC). Источник постановки задачи:
`ТЗ_Две_камеры_измерение_паллет.md`; веб-слой (точки, рабочее место, QR) добавлен поверх него.

**Полная документация** (endpoints, формат QR, настройки) — на `GET /` после запуска сервиса,
в стиле [[wms_optimizer]].

## Принцип измерения

- **Камера top** — footprint (длина × ширина) как bounding box контура, перевод из пикселей в мм
  через гомографию по 4 ArUco-маркерам (плоскость пола).
- **Камера side** — высота и одна видимая сторона паллеты, через 1-2 ArUco-маркера.
- **Коррекция перспективы**: высота от камеры side используется для пересчёта масштаба
  camera top (объект ближе к камере → выглядит крупнее, чем есть).
- **Кросс-проверка**: сторона от камеры side сравнивается со стороной camera top после
  коррекции; расхождение сверх допуска → `cross_check_passed: false`.

Подробности формулы — в ТЗ, раздел 2; реализация — `src/vision/dimensions.py` (без изменений
относительно headless-версии — веб-слой обёрнут вокруг того же протестированного пайплайна).

## Структура

```
app.py                     — FastAPI-приложение: точки, рабочее место, документация
static/, templates/        — CSS + Jinja2-страницы (docs / posts / workplace)
config/post_config.yaml    — конфиг headless-режима (один пост, systemd, без веб-слоя)
src/
  main.py                  — headless-режим: один пост из YAML, без веб-интерфейса
  store.py                 — JSON-хранилище точек (data/posts.json)
  worker.py                — фоновый поток на точку: камеры + пайплайн + live-состояние
  qr.py                    — QR-код с текущими габаритами и весом
  calibration/              — калибровка объектива (chessboard) + ArUco-гомография
  capture/                  — захват синхронизированных кадров с двух камер
  vision/                   — сегментация, расчёт габаритов, стабилизация
  integration/               — отправка события в REST API WMS (retry + буферизация на диск)
  models.py                 — pydantic-модели точки, события, конфигурации
scripts/
  calibrate_post.py         — интерактивная калибровка (ROI/HSV трекбары, детекция ArUco)
  accuracy_test.py          — прогон серии измерений против эталона, вердикт пригодности
tests/                       — юнит-тесты на синтетических данных (без физических камер)
```

## Запуск (веб-сервис, Docker)

```bash
cd services/pallet_dimensioner
cp .env.example .env
# отредактируй CAMERA_TOP_DEVICE / CAMERA_SIDE_DEVICE в .env под /dev/videoN хоста
docker compose up -d
```

- `http://localhost:8012/` — документация
- `http://localhost:8012/posts` — создать/запустить точку (камеры + URL весов из `scale_api`)
- `http://localhost:8012/posts/{id}/workplace` — рабочее место оператора

Для нескольких точек на одном хосте (несколько пар камер) добавь дополнительные `devices:` в
`docker-compose.yml` — Docker пробрасывает конкретные `/dev/videoN`, физически привязанные к
этому хосту; точка на другом физическом посту требует своего контейнера/хоста.

## Локально (разработка)

```bash
cd services/pallet_dimensioner
pip install -r requirements-dev.txt
uvicorn app:app --reload --port 8012
```

### Headless-режим (без веб-слоя, systemd)

Прежний способ — один пост из `config/post_config.yaml`, шлёт напрямую в WMS без UI:

```bash
python -m src.main
```

Юнит `pallet-dimensioner.service` — тот же паттерн, но с `ExecStart=... -m src.main`.

### Тесты

```bash
pytest -q
```

51 юнит-тест на синтетических/фикстурных данных: `vision/`, `calibration/`, `integration/`,
`store/`, `qr/` покрыты независимо от физических камер; `app.py` — smoke-тестами через
`TestClient` (создание/старт/стоп/удаление точки, camera_offline без реального железа). Реальный
`capture/camera_stream.py` и полный цикл `worker.py` — только вручную на посту.

## Калибровка точки

Точка создаётся с разумными дефолтами (весь кадр как ROI, тёмный фон, прямоугольник 1200×800мм
для 4 top-маркеров) — этого достаточно, чтобы увидеть видео и структуру, но не для точных чисел.
Дальше:

1. **Объектив** (разово, опционально): фото шахматной доски под разными углами → `calibrate_lens()`
   → `data/posts/{id}/camera_intrinsics_{top,side}.json`. Без файла просто не корректируется
   дисторсия объектива — сервис не падает.
2. **ROI / HSV / ArUco-координаты**: `PATCH /api/posts/{id}` с нужными полями `camera_top`/
   `camera_side` (см. `scripts/calibrate_post.py` для headless-эквивалента с live-трекбарами —
   тот же принцип, курс на конкретные числа для поста).
3. **Проверка точности**: `python scripts/accuracy_test.py --length 1200 --width 800 --height
   1450` — вердикт «пригодно» при систематической ошибке ≤ 30 мм и std ≤ 15 мм.

## Формат QR-кода (рабочее место)

```json
{
  "post_id": "post-04",
  "post_name": "Пост 04",
  "length_mm": 1195,
  "width_mm": 800,
  "height_mm": 1487,
  "cross_check_passed": true,
  "weight": 820.5,
  "weight_unit": "kg",
  "timestamp": "2026-08-18T10:23:41+00:00"
}
```

## Формат события в WMS (`POST /api/v1/pallet-measurements`, если задан `wms_endpoint`)

```json
{
  "post_id": "POST-04",
  "timestamp": "2026-08-18T10:23:41Z",
  "length_mm": 1195,
  "width_mm": 800,
  "height_mm": 1487,
  "cross_check_passed": true,
  "cross_check_delta_mm": 8,
  "samples_count": 12,
  "measurement_method": "dual_webcam_ortho"
}
```

При сетевом сбое событие буферизуется на диск (`data/posts/{id}/pending_events/`) и досылается
при следующем успешном соединении.

## Известные ограничения / что не входит в этот сервис

- Сопоставление измерения с конкретной паллетой (штрихкод/RFID) — на стороне основного
  FastAPI-бэкенда WMS.
- Обучение ML-модели сегментации — не требуется, пока классическая HSV-пороговая сегментация
  справляется.
- Одна точка = одна пара физически подключённых USB-камер на этом хосте; веб-сервис не умеет
  подключаться к камерам на другом хосте по сети (не RTSP, только локальный `cv2.VideoCapture`).
- Изменения в 1С и основном FastAPI-сервисе WMS — вне этого репозитория.
